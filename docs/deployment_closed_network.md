# Развёртывание в закрытой сети

Документ для инженера, который будет разворачивать систему в сети без выхода
в интернет (R-MEET-01, R-MEET-04).

## Принцип

Система не делает ни одного исходящего соединения. Это не пожелание, а
свойство, проверяемое тестом: `tests/test_metamorphic.py::
test_system_runs_without_any_network_access` подменяет `socket.socket` и
`socket.create_connection` функцией, которая возбуждает исключение, и затем
выполняет полный цикл решения. Если какой-либо модуль попытается выйти в сеть,
тест упадёт.

Дополнительно отключён сбор статистики Streamlit, `.streamlit/config.toml`,
`browser.gatherUsageStats = false`, а сервер запускается в headless-режиме.

## Что нужно на целевой машине

| Компонент | Требование | Примечание |
|---|---|---|
| Python | 3.11 или новее | проверено на 3.13; под 3.10 колёс numpy 2.3.5 и scipy 1.16.3 нет |
| Пакеты | `requirements.txt`, версии закреплены точно | ставятся из локального колеса, см. ниже |
| Диск | ≈ 1,5 ГБ | исходные файлы + канонический слой + модели |
| ОЗУ | ≈ 4 ГБ | телеметрия 189 217 × 97 держится в памяти |
| Сеть | не требуется | никаких внешних адресов |

Библиотека `libarchive` нужна только для автоматической распаковки `data.rar`.
Если её нет, архив распаковывают вручную, система это поддерживает и сообщает
об этом явно.

## Перенос дистрибутива

На машине с интернетом собирается набор колёс:

```bash
pip download -r requirements.txt -d wheelhouse
```

`wheelhouse/` вместе с репозиторием переносится на целевую машину, где:

```bash
python -m venv .venv
source .venv/bin/activate
pip install --no-index --find-links=wheelhouse -r requirements.txt
```

Флаг `--no-index` гарантирует, что pip не обратится к PyPI: установка либо
пройдёт из локального каталога, либо честно упадёт.

## Порядок запуска

```bash
python run_all.py
streamlit run app.py
```

Пакет организаторов входит в репозиторий и лежит в `data/raw/`, обновления в
`data/raw/organizer_updates/`. Переносить данные отдельно не нужно: на целевую
машину достаточно доставить репозиторий и `wheelhouse/`. Каталог с исходниками
только читается, распаковка идёт в `data/interim/unpacked`, рядом с исходниками
ничего не пишется (K-44).

Если данные нужно взять из другого места, каталог задаётся флагом
`--data-dir /путь`; он должен содержать все файлы пакета, включая обновления.

После первого `prepare_data` исходные файлы на машине не нужны: рабочий цикл
читает только канонический слой `data/interim`. Это проверено на чистом клоне
с физически убранным каталогом исходников.

Расчёт за произвольный период, который назовёт жюри или технолог:

```bash
python run_all.py --start 2026-01-01 --end 2026-02-01
python -m scripts.backtest --start 2026-03-01 --end 2026-04-01
```

Результат каждого периода, в `reports/periods/<начало>_<конец>/backtest.json`.

## Подключение к реальному историану

Замена источника не затрагивает агентов, поскольку данные поступают к ним
только через `ProcessState`, построенный на момент `t` и только из прошлого. Для перехода с
исторического воспроизведения на живые данные достаточно реализовать чтение в
том же виде, что и `src/data/loaders.py`, сохранив контракты:

- временной индекс с шагом 10 мин и каноническими именами тегов;
- лабораторные данные в длинном формате с временем отбора пробы;
- значение возраста для каждого измерения.

Система остаётся советующей: она не пишет в АСУ ТП и не имеет для этого
интерфейса. Любое воздействие вносит технолог.

## Локальная LLM (необязательно)

Языковая модель в решении выключена: `config/config.yaml`, `features.llm =
false`. Архитектурно она допускается только как пересказ уже принятого решения
по журналу, через OpenAI-совместимый API локальной модели (R-MEET-02), с
`base_url` внутри периметра. Числа в ответе сверяются с журналом; при
расхождении показывается шаблонный текст. Модель не принимает решений, не
порождает чисел и не может обойти SafetyAgent.

## Что проверить после установки

```bash
python -m pytest tests/ -q          # все тесты, включая тест без сети
python -m scripts.smoke_test        # сквозной цикл решения
python -m src.manifest              # manifest.json: коммит, версии, хэши входов
```

`manifest.json` фиксирует коммит кода, версии пакетов и SHA-256 каждого
исходного файла. По нему проверяется, что на целевой машине работает
поставленная версия кода на поставленных данных.
